# 5. 내 교과로 바꾸기 — 코드 없이 웹에서

"수학 플랫폼이라면서요. 저는 영어 교사인데요."
괜찮다. 이 시스템에서 '수학'은 사실 **프롬프트에 적힌 단어 하나**에 가깝다.
영어·과학·국어·사회, 어느 교과든 **대부분 관리자 웹 화면에서** 바꿀 수 있다.

## 5-1. AI의 성격·말투 = 프롬프트 → 관리자 화면에서

관리자로 로그인 → 상단 **"AI 프롬프트"** 메뉴. 세 가지 프롬프트를 편집·저장하면
**다음 응답부터 바로 반영**된다. 재배포도, 코드도 필요 없다.

- **소크라테스식 문답(챗봇)** — 질문으로 유도하는 튜터의 성격
- **단계별 오류 첨삭** — 풀이를 단계로 나눠 판정하는 기준
- **발문형 힌트** — 정답 대신 사고를 여는 질문

바꾸는 요령: 프롬프트 속 "수학"을 여러분 교과로 바꾸고, 규칙을 다시 적는다.

| 교과 | 규칙 예시 |
|---|---|
| 영어 | "영작문의 문법·표현 오류를 학생이 스스로 발견하도록 질문한다" |
| 과학 | "실험 설계의 허점과 개념 오류를 되물어 찾게 한다" |
| 국어 | "논증 구조와 근거의 타당성을 스스로 점검하게 한다" |

단 하나, **"정답을 직접 주지 않는다"는 원칙만 유지**하면 어느 교과든 잘 맞는다.
이 원칙을 지우면 학생들이 제일 먼저 알아차린다. 시험해 봐서 안다.

## 5-2. 어떤 AI를 쓸지 = API 키·모델 → 관리자 화면에서

관리자 → 상단 **"AI 키·모델"** 메뉴. 여기가 이 시스템의 엔진룸이다.

- **API 키**: OpenAI·Gemini·Claude 중 원하는 것의 키를 붙여넣고 저장.
  각 칸에 **"❓ 키 발급 방법"** 도움말과 **공식 모델 문서 링크**가 달려 있다.
- **모델 추가**: 공식 문서에서 최신 모델 ID(예: `gpt-5-mini`)를 확인해 추가하면
  학생 화면에 선택지로 나타난다. 여러 개 넣으면 학생이 골라 쓴다.
- **일일 한도**: 학생 1인당 하루 질문·첨삭 횟수도 여기서 조정한다.
  시험 기간에 늘렸다가 평소로 되돌리는 식의 운영이 가능하다.

즉 **새 모델이 출시되어도 코드 배포 없이** 관리자가 모델 ID 한 줄만 추가하면
그날 수업부터 쓸 수 있다. AI 업계가 아무리 빨리 달려도 우리는 입력칸 하나로 따라간다.

> 보안 메모: 등록한 API 키는 서버 전용 저장소에 보관되며, 학생 화면으로는
> **절대 내려가지 않는다** (DB 보안정책으로 차단, 실제 검증 완료).
> 학생이 보는 것은 모델 이름 목록뿐이다.

## 5-3. 화면의 메뉴·문구 → 코드 (딱 한 줄 수준)

이건 아직 코드에서 바꾼다. 겁먹을 필요 없다 — 따옴표 안의 글자를 바꾸는 일이다.

| 바꿀 것 | 파일 |
|---|---|
| 학생 사이드메뉴 항목 이름 | `components/student/side-menu.tsx` |
| 사이트 제목 | `app/layout.tsx`, `app/(student)/layout.tsx` |
| 첨삭 방식 버튼 이름 | `components/student/feedback-panel.tsx` |

예: `"💬 소크라테스식 문답"` → `"💬 영어 첨삭 도우미"`.
아니면 클로드에게 "사이드메뉴를 영어 교과에 맞게 바꿔줘" 한 줄로 끝내도 된다.
(자세한 파일 지도는 6장에)

## 5-4. 활동 유형·평가 방식 → 클로드에게

채점 방식이나 활동 종류 자체를 바꾸고 싶으면 클로드에게 설명한다. 예:

```
영어는 정답이 하나가 아니니까, 문제 활동에 '예시 답안'과 '채점 기준'을
넣고 AI가 그 기준대로 채점하게 해줘.
```

요구사항을 한국어로 정확히 말하는 능력 — 그것이 이 시대 교사의 새로운
개발 역량이다. 우리는 이미 수행평가 기준안으로 단련되어 있다.
