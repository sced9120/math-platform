# 늘림 두 번 — 합성함수의 미분법
- id / 과목 / 단원 / 성취기준: calc2-02-05 / 미적분Ⅱ / 미분법 / [12미적Ⅱ-02-05] 합성함수를 미분할 수 있다.
- slug: calc2-chain-stretch
- topic: 미적분Ⅱ · 합성함수의 미분
- summary: x 에서 짧은 구간을 잡아 u = g(x), y = f(u) 두 번 옮겨 봅니다. 구간이 두 번 늘거나 줄어드는 비율을 곱하면 전체 비율이 되고, 구간을 줄이면 (f∘g)′ = f′(g(x))·g′(x) 이 보입니다.
- 높이: 660

## 핵심 아이디어 (왜 이 조작이 이 성취기준인가)
- 미분계수는 "아주 짧은 구간이 몇 배로 늘어나는가(늘림 비율)"다. 합성 y = f(g(x)) 는 x 구간을 g 로 한 번(u 구간), 다시 f 로 한 번(y 구간) 옮긴다.
- 학생이 x 줄에서 구간 [x, x+h] 를 끌어 놓으면, u 줄과 y 줄에 옮겨진 구간이 나타난다. Δy/Δx = (Δy/Δu)·(Δu/Δx) 는 Δu≠0 이면 항상 성립하는 곱셈이다.
- h 를 절반씩 줄이면 Δu/Δx → g′(x), Δy/Δu → f′(g(x)). 그래서 (f∘g)′(x) = f′(g(x))·g′(x). 바깥 함수의 미분을 "x 가 아니라 u = g(x) 에서" 계산해야 하는 이유가 u 줄 위 구간의 위치로 보인다.
- 그래프 대신 평행한 수직선 세 줄을 쓰므로 직전 활동(직사각형·단위원·사인 그래프)과 그림이 겹치지 않고, 2차원 축척이 납작해질 문제가 없다.

## 조작과 반응
- x 손잡이(또는 x 줄 아무 곳 탭)를 끌면 x 가 바뀌고 세 줄의 구간과 연결선, 돋보기 막대, 결과판이 즉시 바뀐다. 축척은 그대로.
- [h 를 절반으로]: h 가 반이 된다. 수직선 위 띠는 얇아져 안 보이게 되지만 돋보기 막대는 x 막대 80px 를 유지하고 u·y 막대가 g′(x)·80, (f∘g)′(x)·80 쪽으로 자리 잡는다. 결과판 왼쪽 값이 오른쪽 공식값에 다가간다. 최소 h 에서 더 누르면 hint "화면에서는 여기까지예요".
- [h 처음으로]: h = 0.5.
- 함수 버튼: 분해 표시·축척 바뀜, x 초기값, h = 0.5.
- [순서 바꾸기]: 같은 두 함수를 반대로 합성(u = f(x), y = g(u))해 g∘f 로 바꾸고 버튼 문구는 [순서 되돌리기 f∘g]. 축척을 새로 정함. 결과판 공식값이 g′(f(x))·f′(x) 로 바뀌어 두 순서의 값이 다름을 볼 수 있다.
- [다시]: 현재 함수·순서 유지, x 초기값, h = 0.5.
- Δu = 0 이 되는 순간(예: ① 에서 정확히 일어나지는 않지만 수치상 |Δu| < 1e−12): 결과판 둘째 줄을 "Δu = 0 이라 나눌 수 없어요"로 바꾸고 셋째 줄 Δy/Δx 는 그대로 보여 준다.

## 수학 계산 규칙
- 함수 쌍(안쪽 g, 바깥 f), x 범위, 초기 x:
  ① g(x)=x², f(u)=sin u. x ∈ [0.2, 1.7], 초기 1. (f∘g)′ = cos(x²)·2x. x=√(π/2)≈1.2533 에서 0 → 탐구 질문에 사용.
  ② g(x)=2x+1, f(u)=u³. x ∈ [−1, 1], 초기 0. (f∘g)′ = 3(2x+1)²·2 = 6(2x+1)². x=−0.5 에서 u=0, f′(u)=0.
  ③ g(x)=sin x, f(u)=eᵘ. x ∈ [0, 3], 초기 1. (f∘g)′ = e^(sin x)·cos x. x=π/2 근처에서 g′=0.
  모두 실수 전체에서 정의되고 미분가능(정의역 예외 없음, 0 나누기는 Δu 나눗셈에만 있음).
- 순서 바꾸기 공식: ① g∘f 아니라 "바깥·안쪽 맞바꿈": u=sin x, y=u² → 2 sin x cos x. ② u=x³, y=2u+1 → 6x². ③ u=eˣ, y=sin u → cos(eˣ)·eˣ. 바뀐 쌍의 x 범위는 같게 둔다.
- h ∈ {0.5, 0.25, …, 0.5/2¹⁰ ≈ 0.000488}, 항상 h > 0. x+h 가 범위 상한을 넘으면 손잡이 x 의 최댓값을 (상한 − h) 로 제한(범위 밖 계산 없음).
- Δu = g(x+h) − g(x), Δy = f(g(x+h)) − f(g(x)). 표시: Δu/h, Δy/Δu (|Δu| ≥ 1e−12 일 때만), Δy/h. 곱 (Δy/Δu)(Δu/h) 와 Δy/h 가 1e−9 이내로 같아야 함.
- 각 줄 축척: 함수(와 순서)가 정해지면 x 범위 전체에서 그 줄 값의 최솟값~최댓값을 구해(촘촘한 표본 400개) 5% 여백을 더한 고정 범위. 예: ② 순서대로면 y 줄 [−1, 27].
- 돋보기 배율: 막대 길이 = 80 × (구간 길이)/h px, 클리핑은 화면 폭 기준(세로선 x=150 에서 왼쪽 6px 지점·오른쪽 폭−6px 지점).

## 안내 문구와 탐구 질문
- hint 기본: "초록 구간을 끌어 보세요. g 로 한 번, f 로 또 한 번 옮겨지며 늘거나 줄어요."
- hint h 를 줄일 때: "h 를 절반씩 줄여 보세요. 돋보기 막대 길이는 어떤 값에 다가가나요?"
- hint 순서 바꿀 때: "같은 두 함수를 반대 순서로 합성했어요. 늘림 비율도 같을까요?"
- hint 최소 h: "화면에서는 여기까지예요. 실제 미분계수는 h → 0 일 때의 값이에요."
- 탐구 질문:
  1. 전체 비율 Δy/Δx 는 두 번의 비율 Δu/Δx, Δy/Δu 와 어떤 관계인가요? h 를 바꿔도 그 관계가 유지되나요?
  2. h 를 줄이면 Δy/Δu 는 f′(x) 와 f′(g(x)) 중 어느 쪽에 다가가나요? u 줄에서 구간이 어디에 있는지 보고 이유를 말해 보세요.
  3. ① 에서 y 막대가 0 이 되는 x 를 찾아 보세요. 그때 멈춘 것은 첫 번째 늘림인가요, 두 번째 늘림인가요? ③ 에서는 어떤가요?
  4. [순서 바꾸기]를 눌러 g∘f 와 f∘g 의 미분계수를 비교해 보세요. 합성의 순서가 왜 중요할까요?

## 제작 난이도 판단
보통 — 계산은 단순하지만, 세 줄 고정 축척·뒤집힘 빗금·돋보기 클리핑과 360 폭에서 눈금 숫자·꼬리표가 겹치지 않게 배치하는 데 손이 간다.

## 점검 포인트
1. 연쇄법칙 (f∘g)′(x) = f′(g(x))·g′(x) 와 세 쌍(및 순서 바꾼 쌍)의 공식값이 맞는지: ① 2x cos(x²), ② 6(2x+1)², ③ e^(sin x)cos x; 바꾼 쌍 2 sin x cos x, 6x², eˣcos(eˣ).
2. Δy/Δx = (Δy/Δu)(Δu/Δx) 가 Δu≠0 에서 정확한 항등식이고, Δu=0 일 때 나누지 않는지.
3. 최소 h(≈0.000488)에서 각 근삿값과 공식값 차이가 대략 0.01 이하(전진차분 O(h)), 문구가 '유한 단계 근삿값'임을 밝히는지.
4. 축척이 끌기·h 줄이기에 따라 흔들리지 않고, 1차원 줄이라 가로세로 비가 왜곡되지 않는지. 돋보기 막대 길이 = 80·비율 이 결과판 숫자와 일치하는지.
5. 390·360×660 첫 화면(details 접힘)에서 hint·함수 버튼·수직선·돋보기·결과판·조작줄 bottom ≤ 660, 눈금 숫자·꼬리표·막대 숫자 겹침 없음.
