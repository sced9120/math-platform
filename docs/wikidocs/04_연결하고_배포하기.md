# 4. 연결하고 배포하기

코드가 있어도 데이터베이스·AI와 연결되지 않으면 빈 껍데기다.
이 장에서 열쇠(키)를 꽂고, 인터넷에 공개한다.

## 4-1. 연결 정보 넣기 — `.env.local`

프로젝트 폴더의 `.env.local` 파일에 열쇠들을 넣는다. 클로드에게 이렇게 시키면 된다:

```
.env.local.example 을 참고해서 .env.local 을 만들 건데,
값은 내가 붙여넣을게. 어디서 발급받는지 알려줘.
```

꼭 필요한 값 (Supabase → Project Settings → API에서 복사):

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

AI 키(`OPENAI_API_KEY` 등)는 여기 넣어도 되지만, **배포 후 관리자 화면
"AI 키·모델"에서 등록하는 쪽이 더 쉽다** (5장 참고). 환경변수를 안 만져도 되니까.

> ⚠️ `.env.local`은 **절대 인터넷에 올리거나 남에게 보여주면 안 된다.**
> 이 파일이 곧 학교 창고 마스터키 꾸러미다. (git이 자동으로 업로드에서 제외해 준다)

## 4-2. 데이터베이스 만들기

Supabase 대시보드 → **SQL Editor**에 `supabase/setup.sql` 전체를 붙여넣고 **Run**.
표·보안정책·함수가 한 번에 만들어진다.

> 이미 운영 중인 DB에 **기능 추가 SQL만** 반영할 때는 setup.sql을 다시 돌리면
> "already exists" 오류가 난다. 그때는 `supabase/migrations/`에서 새 번호 파일만
> 골라 실행한다. 헷갈리면 클로드에게 "지금 DB에 뭘 실행해야 해?"라고 물어보자.

## 4-3. 관리자 계정 만들기 (최초 1회)

```bash
npm run create-teacher -- admin 관리자 --admin
```

출력된 아이디/초기비밀번호로 로그인 → 비밀번호 변경 → 이후 교사·학생 계정과
AI 설정 전부를 웹 화면에서 관리한다.

## 4-4. 로컬에서 확인 후 배포

```bash
# 내 컴퓨터에서 먼저 실행해 보기
npm run dev
# → http://localhost:3000 을 브라우저로 열어 로그인까지 확인

# 문제 없으면 인터넷에 공개
npx vercel --prod
```

처음 `vercel` 명령을 쓰면 로그인·프로젝트 생성 안내가 나온다. 배포 후
Vercel 사이트의 **Environment Variables**에 `.env.local`의 값들을 등록해야
실제로 작동한다. (방법이 기억 안 나면 클로드에게 물어보면 된다 — 필자도 그랬다)

1~2분 뒤 `https://프로젝트이름.vercel.app` 주소가 생긴다. 축하한다.
이제 여러분은 "우리 학교 사이트 있어요"라고 말할 수 있는 교사다.

## 4-5. (선택) 나만의 도메인 붙이기

도메인을 샀다면:

1. Vercel 프로젝트 → **Settings → Domains** → 도메인 입력
2. 도메인 구매처(또는 Cloudflare) DNS에 CNAME 레코드 추가
   (`math` → `cname.vercel-dns.com` 형태)

몇 분 뒤 내 도메인으로 접속되고, https 보안 인증서는 Vercel이 알아서 발급한다.
