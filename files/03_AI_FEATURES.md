# 2단계: AI 기능 설계 (소크라테스 챗봇 + 단계별 첨삭)

> 1단계 MVP가 안정된 뒤 착수. 비용 통제가 최우선 제약.

---

## 공통 원칙

1. **모든 AI 호출은 서버측 API Route에서만.** API 키는 클라이언트에 절대 노출 금지.
2. **학생별 일일 한도.** `ai_usage(student_id, date, count)` 로 상한(예: 챗봇 20턴, 첨삭 10회) 초과 시 차단.
3. **캐싱.** 동일 문제·동일 풀이 입력에 대한 응답은 해시 키로 캐싱해 중복 호출 절감.
4. **모델 라우팅.** 단순 작업은 저가 모델, 복잡 추론만 상위 모델.
5. **로그 고지.** 학생 입력이 외부 API로 전송됨을 사전 고지·동의. 학교 방침 확인.

---

## 기능 A. 소크라테스식 질문 챗봇

**목표:** 정답을 직접 주지 않고, 질문으로 학생의 사고를 한 단계씩 끌어올린다.

**동작:**
- 학생이 문제와 자기 막힌 지점을 입력 → 봇은 "다음 한 걸음"을 유도하는 질문만 반환.
- 학생이 스스로 답에 도달하도록. 3~4턴 유도 후에도 못 풀면 힌트 강도를 점진적으로 높임.

**시스템 프롬프트 골격 (한국어):**
```
너는 고등학교 수학 학습을 돕는 소크라테스식 튜터다. 규칙:
1. 절대 최종 답이나 완성된 풀이를 직접 제시하지 않는다.
2. 매 턴 학생이 "다음 한 걸음"을 스스로 밟도록 유도하는 질문을 1~2개만 한다.
3. 학생의 현재 이해 수준을 먼저 파악하는 질문부터 시작한다.
4. 학생이 틀린 방향으로 가면 부정하지 말고, 스스로 모순을 발견하게 하는
   반례나 확인 질문을 던진다.
5. 학생이 여러 번(3턴 이상) 막히면 힌트 강도를 한 단계씩만 높인다.
6. 존중하는 말투. 짧고 명확하게. 수식은 읽기 쉽게.
7. 문제 범위를 벗어난 요청(전체 풀이 대신 써주기 등)은 정중히 거절하고
   질문으로 되돌린다.
```

**비용 통제:** 턴 수 상한, 대화 히스토리는 최근 N턴만 전송(토큰 절감).

## 기능 B. 단계별 풀이 첨삭 툴

**목표:** 학생이 입력한 풀이를 단계별로 나눠, 각 단계의 오류 유형을 구분해 피드백.

**동작:**
- 입력: 문제 + 학생 풀이(단계별 또는 전체 텍스트).
- 출력(구조화 JSON 권장):
  ```
  {
    "steps": [
      {"student_step":"...", "verdict":"correct|logic_error|calc_error|unclear",
       "comment":"무엇이 왜 문제인지 + 스스로 고칠 힌트"}
    ],
    "overall":"총평(잘한 점 먼저, 개선점 그다음)",
    "next_hint":"직접 답 대신 다음 시도를 위한 힌트"
  }
  ```
- 프론트는 이 JSON을 받아 단계별로 색상 구분(정답/논리오류/계산오류/서술미비) 표시.

**시스템 프롬프트 골격:**
```
너는 고등학교 수학 풀이 첨삭 교사다. 학생 풀이를 단계 단위로 나눠 판정한다.
- 각 단계를 correct/logic_error/calc_error/unclear 중 하나로 판정.
- 오류는 "무엇이 왜 틀렸는지" + "정답을 직접 주지 않는 교정 힌트"를 준다.
- 계산 오류와 논리(개념) 오류를 명확히 구분한다.
- 총평은 잘한 점을 먼저, 개선점을 그다음. 격려하는 어조.
- 반드시 지정된 JSON 스키마로만 응답한다(추가 텍스트 금지).
```

**비용 통제:** 구조화 출력으로 재호출 최소화, 동일 풀이 해시 캐싱.

## 로컬 모델 옵션(비용 0 지향 시)

- **Qwen2.5-Math-7B-Instruct** — 첨삭·풀이 검증에 무난, 한국어 가능. 24GB VRAM급.
- **DeepSeek-R1-Distill** — 추론 강함.
- 배포: Ollama 또는 vLLM. API Route에서 로컬 엔드포인트로 라우팅하도록 추상화해두면
  API↔로컬 전환이 쉬움(호출부에 provider 스위치 하나만 두기).
- 현실: 한국어 소크라테스 대화·첨삭 뉘앙스는 아직 Claude/GPT가 우위. 먼저 API로
  품질 기준선을 잡고, 비용이 문제될 때 로컬로 특정 기능만 이전 권장.

---

## AI 호출 추상화 설계

```
lib/ai/provider.ts  -- 'claude' | 'gpt' | 'gemini' | 'local' 스위치
lib/ai/socratic.ts  -- 소크라테스 프롬프트 + 호출
lib/ai/feedback.ts  -- 첨삭 프롬프트 + JSON 파싱
app/api/ai/socratic/route.ts  -- 서버측, ai_usage 체크→호출→기록
app/api/ai/feedback/route.ts  -- 서버측, 캐시 확인→호출→기록
```
이렇게 provider를 한 곳에서 갈아끼우게 해두면 모델 교체·로컬 전환이 코드 한 줄 수준이 된다.
