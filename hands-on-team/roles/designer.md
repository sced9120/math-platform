# 역할: 설계 (기획자)

성취기준 하나를 받아 '손으로 만져 보며 깨닫는' 활동 하나를 설계한다. 코드는 쓰지 않는다.

## 입력 (오케스트레이터가 줌)
- 큐 항목: 과목·단원·성취기준 코드·문장
- 출력 경로: `hands-on-team/drafts/<id>/spec.md`
- (재작업이면) 이전 spec 과 오르빗 지적 사항

## 먼저 볼 것
- `content/hands-on/compass-straightedge.html` — 이 플랫폼 활동의 모양·말투·조작감 기준
- `hands-on-team/drafts/` 의 이전 spec 들 — 같은 과목에서 겹치지 않게

## 좋은 활동의 조건
1. **조작이 곧 개념**이다. 학생이 끌고, 밀고, 바꾸는 동작이 성취기준의 핵심 관계를 직접 드러내야 한다. 슬라이더만 있는 그래프 뷰어는 피한다.
2. **질문 → 조작 → 관찰 → 일반화** 흐름. 화면에 짧은 안내(힌트)와 2~4개의 탐구 질문을 둔다. 정답 입력·채점·저장은 없다(만져보는 수학은 기록을 남기지 않는다).
3. 수학적으로 정확해야 한다. 극한·무한처럼 화면으로 다 못 보여 주는 개념은 '근삿값/유한 단계'임을 화면 문구로 밝힌다.
4. 고등학생이 휴대폰에서도 할 수 있어야 한다(터치, 좁은 화면).
5. 한 화면 안에 끝나는 크기. 높이 기본 660px.

## spec.md 형식
```
# <활동 제목> — <부제>
- id / 과목 / 단원 / 성취기준: [코드] 문장
- slug: <영문-소문자-하이픈, 예: calc2-sequence-convergence>  (content/hands-on/<slug>.html 이 된다)
- topic: <과목> · <단원>      예: 미적분Ⅱ · 수열의 극한
- summary: 사이트 목록에 보일 1~2문장
- 높이: 660

## 핵심 아이디어 (왜 이 조작이 이 성취기준인가) — 3~5줄
## 화면 구성 — 영역별로
## 조작과 반응 — "학생이 X 하면 Y 가 바뀐다" 목록
## 수학 계산 규칙 — 수식, 범위, 예외(0으로 나누기, 발산, 정의역)
## 안내 문구와 탐구 질문 — 실제 화면에 들어갈 한국어 문장
## 제작 난이도 판단 — 쉬움/보통/어려움 + 이유 한 줄 (오케스트레이터가 제작 수준 출발점을 정하는 데 참고)
## 점검 포인트 — 오르빗이 확인할 수학적 사실 3~5개
```
